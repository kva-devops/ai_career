ОТЧЁТ ПО SQL-БАЗЕ И ТЕСТИРОВАНИЮ
Проект: Career Navigator для Java-разработчиков
Дата: 17.10.2026

1. Краткое описание SQL-таблиц

users
Основная таблица пользователей. Хранит UUID пользователя, email, имя, хэш пароля, роль (client/admin), даты создания и изменения.

profiles
Профиль пользователя. Связан с users по user_id. Содержит роль, опыт, навыки, образование, возраст, регион, формат работы, зарплатные ожидания, время обучения, горизонт цели и интерес к управлению.

dialogues
Диалоги пользователя с консультантом. Связан с users по user_id. Хранит название диалога и даты создания/обновления.

messages
Сообщения внутри диалогов. Связан с dialogues по dialogue_id и с users по user_id. Хранит отправителя (user/assistant/system), текст, метаданные ответа и дату создания.

memory_facts
Долгосрочная память пользователя. Связан с users по user_id. Хранит название факта, значение, источник и даты изменения. Для одного пользователя и одного field_name действует уникальность.

resume_documents
Загруженные резюме пользователя. Связан с users по user_id. Хранит имя PDF-файла, тип, размер, полный извлечённый текст, структурированные результаты анализа, источник извлечения и статус обработки.

career_plans
Сохранённые карьерные планы и версии выбранных треков. Связан с users по user_id и, при наличии, с dialogues по dialogue_id. Хранит статус, выбранный трек и JSON-план.

agent_runs
Запуски этапов агентной обработки карьерного плана. Связан с users и опционально с career_plans. Фиксирует этап, версию промпта, контекст, статус, ошибки и время выполнения.

sessions
Сессии авторизации. Связана с users по user_id. Хранит хэш сессионного токена, срок действия и дату создания.

Связи и безопасность
- При удалении пользователя связанные профиль, диалоги, сообщения, память, резюме и планы удаляются каскадно.
- Сообщения доступны только через диалог, принадлежащий текущему пользователю.
- Административные маршруты дополнительно проверяют роль admin.
- Пароли не хранятся в открытом виде, используется PBKDF2-хэширование.

2. Методика тестирования

Для проверки были созданы два временных тестовых клиента. Их данные после завершения тестов удалены из базы. Сервер приложения использовал модель gpt-4o-mini (значение по умолчанию для ProxyAPI).

3. Результаты тестирования

Сценарий 1. Память текущего диалога — PASS

Проверка:
- В один диалог отправлены два последовательных сообщения.
- В первом сообщении зафиксирована технология Kafka.
- Во втором сообщении задан вопрос о технологии из предыдущего сообщения.
- Проверена SQL-история сообщений.

Результат:
Четыре сообщения сохранились в одном диалоге, а следующий ответ агента использовал Kafka из предыдущего сообщения.

Сценарий 2. Долгосрочная память между диалогами — PASS

Проверка:
- В профиль записан горизонт цели «3 месяца».
- В таблицу memory_facts записан долгосрочный факт.
- Создан новый диалог.
- В новом диалоге задан вопрос о цели пользователя.

Результат:
Данные сохранились в PostgreSQL и были доступны агенту после перехода в новый диалог.

Сценарий 3. Изменения SQL влияют на последующие ответы — PASS

Проверка:
- В SQL изменены роль пользователя на «Backend Architect» и горизонт цели на «18 месяцев».
- После изменения отправлен новый запрос агенту.

Результат:
Ответ агента использовал новые значения из базы: Backend Architect и 18 месяцев. Старые значения не использовались.

Сценарий 4. Изоляция данных клиентов — PASS

Проверка:
- Созданы два клиента с разными диалогами и секретными сообщениями.
- Клиент A попытался запросить сообщения из диалога клиента B.
- Клиент A попытался обратиться к административному API другого пользователя.
- Проверено отсутствие секрета клиента B в ответах клиенту A.

Результат:
- Чужие сообщения не возвращаются.
- Административный API для обычного клиента возвращает HTTP 403.
- Данные клиента B не попали в контекст и ответы клиента A.

Итог: 4 из 4 сценариев пройдены успешно.

4. Артефакты тестирования

Повторяемый тестовый сценарий сохранён в файле:
qa-memory-security.mjs

Тестовый раннер подключается к локальному приложению и PostgreSQL, выполняет проверки и удаляет временные аккаунты после завершения.
